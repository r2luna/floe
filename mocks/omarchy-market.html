Development

Develop a custom plugin

Updated 13 Sep 20269 min readStable

Build in your user-owned plugin directory, start from a working built-in, and validate the finished folder with the same manifest rules the plugin host enforces at boot.

Plugins share Floe's plugin host process and run with your user permissions. Review every dependency, avoid unnecessary privileges, and keep state inside ctx.dir.

01Clone a built-in plugin

Pick the built-in with the same kind and interaction pattern as the plugin you want. This tutorial builds a panel with row actions, so the built-in hello panel is the closest start.

1Match the contractSame kind, same dispatch shape.
2Work in a user copyEdit under ~/.config/floe, never Floe's source.
3Expect an immediate loadThe clone is discovered and enabled at once.
Terminal · create local copy
floe plugin clone floe.hello --edit
Files · local plugin
~/.config/floe/plugins/yourname.hello/
├── manifest.json
├── src/main.ts
└── dist/main.cjs

02Define the plugin contract

Plugin kindRegisters viaUse it for
commandctx.registerCommandsPalette rows, bindable keys
toolctx.registerToolMCP tools beside the built-ins
panelctx.registerPanelDeclarative panel with Settings rows
uictx.registerUiIsolated custom document (v2)
backendctx.backends.setRemote Floe backends
harnessctx.registerHarnessA new agent runtime
JSON · manifest.json
{
  "name": "yourname.hello",
  "version": "1.0.0",
  "author": "Your name",
  "license": "MIT",
  "description": "A small panel with row actions.",
  "main": "dist/main.cjs",
  "apiVersion": 2,
  "minFloeVersion": "0.40.0",
  "kinds": ["panel", "command", "tool"],
  "floe": { "clonedFrom": "floe.hello" }
}

03Implement the panel

Section ids name the plugin's own commands, so a panel row, its ⌘K entry and its MCP tool are one dispatch.

JS · src/main.ts
module.exports = {
  activate(ctx) {
    ctx.registerCommands([{ id: 'greet', title: 'Say hello', run: () => ctx.log('hello!') }])
    ctx.registerTool({ name: 'hello_status', description: 'Report status.', run: () => ({ ok: true }) })
    ctx.registerPanel({ id: 'main', title: 'Hello',
      body: () => [{ kind: 'list', rows: [{ id: 'greet', label: 'Say hello' }] }] })
  }
}

04Validate the folder

Terminal · validate
floe plugin validate ~/.config/floe/plugins/yourname.hello
  • Manifest parses as JSON — name, version, main, apiVersion present
  • Kinds and registrations agree — a panel kind must call registerPanel
  • Every referenced file exists — main resolves inside the plugin dir
  • No forbidden id or symlink — third-party ids cannot use floe.*

05Run and inspect

Terminal · inspect status
floe plugin list
yourname.hello  1.0.0  enabled  panel command tool

From the app: ⌘K → Plugins: reload. From an agent: list_plugins on the MCP server.

Publishing

Publish your plugin

Updated 13 Sep 20263 min readStable

List your plugin in three steps. Keep the code in a public git repository and ship a prebuilt dist/ with a valid manifest.json.

The marketplace validates listings, not plugin security. You remain responsible for your code, assets, documentation and license.

01Prepare the repository

  • Public git repository (GitHub or Forgejo)
  • Valid manifest.json in the repository root
  • Prebuilt dist/main.cjs committed — no build at install
  • README and license
  • Safe install and removal
  • Optional preview image, optimized automatically

02Add a manifest

Run floe plugin clone, then floe plugin validate.

FieldPurposeRequired
nameKebab-case slug, namespaces everything the plugin registersYes
versionCurrent version, shown in the marketplaceYes
mainCJS bundle exporting activate(ctx)Yes
apiVersionAdditive plugin API gateYes
authorShown in the marketplaceYes
descriptionShort marketplace summaryYes
kindsSurfaces the plugin registersYes
minFloeVersionRefuse to load on an older FloeNo

03Submit your plugin

Open the issue form with your repository link, category and tags. Automated validation checks the current commit before a maintainer approves the listing.
