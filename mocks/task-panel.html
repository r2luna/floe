A panel per project where half-baked ideas live until they are ready. One list, one item view. Each task is a folder so plans, designs and drawings sit beside the idea.

When it is ready, one key sends it to the colony.

plan p edit · plan.md

Storage

  • One folder per task: .floe/tasks/NNN-slug/, committed.
  • task.md holds title, status and kind in its header, the idea in its body.

Panels

  1. tasks list on the rail, ⌘K T, grouped by status.
  2. task item, opened from a row. Renders idea and plan in place.

Send

  • git mv the folder to specs/, commit, start the colony card.

  • The list reads .floe/tasks/* (idea → ready) and specs/NNN-* (in dev, done) from the project's main checkout. The number sorts nothing; groups sort by status, newest first inside a group.
  • The item view renders plan.md in place, under the idea. It is never a row you open. With no plan yet the section says so and p creates it.
  • Files are one left-aligned column: icon and name, nothing else. The icon says the type: ◧ html, ✎ drawing, ↗ link, ▤ any other file. ⏎ picks the panel from it: html and links → preview browser (file://), drawings → draw, the rest → reader.
  • n opens a one-line prompt for the title. The task starts as idea with an empty body.

  • The number is three digits, zero-padded, one higher than the highest number in either .floe/tasks/ or specs/. It never gets reused.
  • Floe only ever writes task files in the main checkout, and only commits them on master. It never writes them in a worktree.
  • The colony branch is cut from master after the move commit, so the lanes can read specs/017-…/. Their brief says it is read-only.
  • The card's lanes write their own documents into specs/017-…/colony/, one folder per task. The card carries that folder as specDir, so no second specs/feat-017-…/ folder appears.
  • Done is never written. A task in specs/ shows done once its card is merged, so no commit lands on master after the merge (which would block the colony's undo).
C5 what ⌘⏎ does
  1. Refuse unless the status is ready. The button is greyed and says why.
  2. Refuse unless the main checkout is on master. Other dirty files there are fine and stay untouched.
  3. In the main checkout: git mv .floe/tasks/017-… specs/017-…, set status in dev, commit both paths: chore(tasks): start 017-task-panel-for-ideas.
  4. Create the colony card and start it: name 017-task-panel-for-ideas, kind from task.md, lanes writing in specs/017-…/colony/. After the commit, so the worktree is cut from a master that has the folder. Starting it straight away is what ships today. C8 would hand it to the nanny instead.
  5. Sending again finishes whatever the last send did not: it creates a missing card, or starts one still in the backlog.

C8 colony intake — the nanny checks every card, and follows up on every hand-off
  1. Every new card lands in inbox, not started. The source does not matter: the task panel, colony_add_task from any agent, or n on the board. The board records an added event.
  2. The board wakes the nanny. Today it only wakes a nanny that already exists. Intake needs her always, so the board creates her when she is missing.
  3. She triages the card, reading the brief and the task folder, and does one of three things:
    a) fits one worktree → colony_start_task.
    b) too big → cuts a parent branch feat/017-slug from master, adds one child card per piece with base = that branch and dependsOn in order, starts them. The inbox card becomes the parent record: "split into 3".
    c) unclear → asks you one question. The card stays in inbox.
  4. She schedules a follow-up on herself with create_followup (5 min): "verify the hand-off of cards X, Y". One pending follow-up per board. New cards join it instead of stacking a second one (list_followups).
  5. The follow-up checks each card against the table below. What she can fix she fixes. What she cannot, she tells you in one line.
  6. Every later stage move repeats 4–5 for that card. Each stage runs in a new session (D28), so every hand-off to a lane is a new chance for the brief not to arrive. The chain stops when no card has an unchecked hand-off.
  7. Split tasks close on the parent. When the last child merges into feat/017-slug, she merges the parent into master. Then the task shows done.
