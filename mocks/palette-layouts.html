Palette — 6 layouts

The same three uses in every proposal: switch project, find a file, run a command. Boxes are drawn at 340px so the three fit side by side; the shipping palette is 580px wide and every proposal scales with it.

Current — one row shape for three very different lists

F1 a file row is the whole path at full strength, so the basename — the only part you are scanning for — has no weight, and .palette-title is flex:none, so a long path runs off the right edge with no ellipsis. F2 a project's group and machine sit at the far right, a screen away from the name they describe. F3 commands read group: title as one lowercase string. F4 only the command palette has a footer, so the same box teaches its keys in one use and hides them in the other two.

With an empty query the list is grouped and sticky-headed — recents first, then groups for projects, open panels for files, the command's own group for commands. The headers drop the moment you type, because ranking beats grouping once there is a query.

P4 — Split preview

List on the left, the highlighted row explained on the right: the head of the file, what a command does and where it is bound, a project's worktrees and live sessions. Turns ⌘K into something you can browse, not only fire. Costs width (700px) and a second thing moving as you arrow. Composes with P1/P2 — the left column can use either row shape.

P5 — Anchored to the panel it filters

No window-wide overlay for the list-shaped ones: the file search drops into the files panel's own head and filters the tree in place, the project switch filters the projects panel. Nothing is covered, and the result appears where it already lived. The command palette stays centred — it belongs to the window, not to a panel.
